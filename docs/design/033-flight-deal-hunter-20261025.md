# 低价机票猎人（Flight Deal Hunter）设计（033）

> 日期：2026-10-25
> 依赖：031 通用 Web 任务引擎 / 032 无头模式；复用 web_task、run_subagents、recipes、ask_user、render_ui、schedule_task、memory
> 状态：**设计文档** — 不含任何实施承诺

---

## 1. 目标与范围

### 做

- **多目的地组合搜价**：「27 年五一上海飞各个地方的低价机票」——枚举目的地（热门榜单 / 用户圈定）× 日期组合，并行搜索各 OTA，汇总低价列表
- **需求引导**：时间（去程/回程或单程区间）、出发城市、预算区间、目的地偏好（国内/海外/海岛/任意）、直飞/中转、人数
- **结果呈现**：按价格排序的表格 + 可交互筛选面板；每条附**直跳预订链接**（用户自行预订——我们不代订）
- **降价监控（进阶）**：把搜索条件存成订阅，定时重查，低于目标价通知

### 不做（边界）

- ❌ 代订 / 代付：结果卡直跳 OTA 链接，下单永远人工
- ❌ 突破 OTA 风控：无头被拦即降级换源，不硬刚
- ❌ 保证全量比价：只做「主流 OTA + 聚合源」覆盖，不是 GDS

## 2. 用户交互流

```
用户: "帮我收集 27 年五一上海飞各个地方的低价机票"

① 需求补全（ask_user 选项卡，缺什么问什么）
   ┌────────────────────────────────────┐
   │ 出发城市: 上海（默认取记忆）         │
   │ 行程类型: 单程 / 往返（五一默认往返） │
   │ 去程日期: 2027-05-01 ±2 天灵活？     │
   │ 回程日期: 2027-05-04 ±2 天灵活？     │
   │ 目的地: 任意低价 / 国内热门 / 我列几个 │
   │ 预算: 单程 ≤¥500？往返 ≤¥1200？      │
   │ [开始搜索]                          │
   └────────────────────────────────────┘
   日期灵活 → 按 ±N 天展开日期组合（上限：单程 ≤5 个日期、往返 ≤3×3）

② 目的地枚举（无明确目的地时）
   - 内置热门榜单（国内 ~40 城 / 周边 ~15 城，常量表）
   - 每个目的地生成一条「航线×日期组合」搜索任务

③ 并行搜索（run_subagents 或主 agent 串行 web_task，见 §4）
   SSE 实时反馈：已查 12/40 条航线……

④ 汇总呈现
   - Markdown 表格（价格升序 Top 20）+ 完整结果附件
   - render_ui 可交互面板：按价格/时长/航司/直飞筛选排序
   - 每条: 目的地 ¥价格 日期 航司 直飞/中转 时长 [预订链接]
   - 预算内标绿；明显低价（低于历史 P20）标"🔥"

⑤ 可选订阅: "帮我盯着这条线，低于 ¥800 叫我"
   → schedule_task 定时重查 + events 通知
```

## 3. 数据源策略（三层，诚实评估）

| 层 | 来源 | 方式 | 稳定性 |
|----|------|------|--------|
| L1 结构化优先 | Trip.com / 携程国际版（英文站反爬弱）、Skyscanner 网页、Google Flights | **可构造搜索 URL**（`/flights/shanghai-to-tokyo/2027-05-01`）→ web_fetch 或 web_task 无头打开 → extract 结果列表 | 高（URL 稳定、结构清晰） |
| L2 OTA H5 | 携程/去哪儿/飞猪 H5 搜索页 | web_task 无头 + 配方（选择器/怪癖） | 中（JS 重、偶发风控，被拦即换源） |
| L3 聚合兜底 | web_search「上海飞XX 特价 5月」+ 内容站/聚合页 | web_search + web_fetch | 低（信息零散，仅补漏） |

原则：**每条航线任务独立选源**——L1 可得就不碰 L2；全部失败标记「该航线查询失败」不阻塞整体。价格抓取以「含税总价」为准，抓不到税费的标注「未含税」。

## 4. 搜索编排

```
航线×日期组合任务（例：上海→成都 5/1 单程）
  ├ 优先 run_subagents 并行批（8 并发上限已有）：每子任务 = 1 条航线 × 1 日期组
  │   子任务用 web_fetch/web_task（只读，无需 confirmed）抽结构化:
  │   [{目的地, 日期, 价格, 航司, 航班号, 起降时间, 直飞, 时长, 预订URL, 抓取源}]
  └ 汇总器（主 agent）: 合并 → 同航线多源去重（取最低价）→ 排序 → 渲染
```

- **规模护栏**：单轮 ≤40 个航线任务（48 并发上限内分批）；每任务步数上限/超时沿用引擎默认
- **缓存**：同会话 30 分钟内同参数不重查（memory 或会话内 dict）
- **失败语义**：单航线失败 ≠ 整体失败，结果表注明

---

## 5. 结果呈现

- **正文表格**（价格升序 Top N）+ `notes` 附件存全量 JSON（可再问「只看海岛」「周四出发的」二次筛选，不再抓取）
- **A2UI 面板**（render_ui）：数据表 + 价格滑杆 + 直飞开关 + 目的地搜索框——面板操作回流的筛选不重查
- 预订链接打开方式：正文 Markdown 链接（用户点击在系统浏览器打开），**不走专用浏览器**

---

## 6. 降价订阅（进阶）

- 「盯着这条线低于 ¥X 通知我」→ schedule_task（默认每日 10:00）跑一次定向查询（单航线 1-2 任务）
- 低于阈值 → 系统通知（复用 task_finished 通知通道）+ 会话消息
- 订阅记录存 memory（`flight_watch.*`），可在对话里「取消盯票」

---

## 7. 站点配方

每源一个 recipe（`recipes_builtin/flight_*.json`）：

```json
{
  "name": "trip-com-flights",
  "url_patterns": ["*trip.com/flights*", "*trip.com/flight/*"],
  "flow_hints": "搜索 URL 形如 /flights/{from}-{to}/{date}；结果卡选择器…含税价在 .price-txt…",
  "extract_templates": {"results": "…"},
  "quirks": ["首屏有 cookie 弹窗先关", "价格默认每人含税"]
}
```

配方失效 → 退 L3 兜底 + 上报需更新（引擎既有机制）。

## 8. 分期

| 阶段 | 内容 | 量级 |
|------|------|------|
| A | 需求收集卡 + 目的地常量表 + L1 源（Trip.com 优先）单程搜价 + 汇总表格 | 2-3 天 |
| B | 往返组合、灵活日期展开、多源去重、A2UI 筛选面板 | 2 天 |
| C | L2 OTA H5 配方（携程/去哪儿）、抓取失败降级链 | 按站点各 0.5-1 天 |
| D | 降价订阅 + 通知 | 1 天 |
