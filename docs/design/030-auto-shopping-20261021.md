# 自动购物下单 / 点外卖 功能设计（独立设计，不依赖 Computer Use）

> 日期：2026-10-21
> 目标：Agent 代替用户完成"搜索 → 比价 → 选规格 → 加购 → 生成订单"的购物全流程，支付环节强制人工。
> 技术路线：**Browser Use（DOM 级浏览器自动化）**——接管用户真实浏览器，零系统权限，与 Computer Use 无关。
> 状态：**设计文档** — 不含任何实施承诺。

---

## 1. 目标与范围

### 做
- 网页版电商平台：美团/饿了么（外卖）、淘宝/京东（购物）
- 半自动模式为主：Agent 备单，人支付
- "老规矩"例行复购（偏好记忆 + 定时任务）
- 下单后订单状态追踪

### 不做（永久边界）
- ❌ 自动支付（密码/免密/刷脸一概不碰）
- ❌ 自动过验证码（滑块/短信）
- ❌ 移动端 App 自动化
- ❌ 微信小程序场景（需全屏视觉操作，属另一能力线，本设计不涉及）
- ❌ 平台 OpenAPI 逆向

---

## 2. 技术路线：Browser Use 主通道

**核心决策：CDP attach 用户真实浏览器，而非无头浏览器。**

| 维度 | CDP attach 真实浏览器（选定） | 无头 Playwright（不采用） |
|------|------------------------------|---------------------------|
| 登录态 | 天然复用（用户已登录） | 需要账号自动化，踩平台红线 |
| 风控指纹 | 真实浏览器，暴露面最小 | 无头特征易被识别 |
| 支付 | **用户就在这个浏览器里支付**，Agent 监听 DOM 验证结果 | 支付跳转后断链 |
| TCC 系统权限 | **零权限** | 零权限 |

接入方式：检测/引导 Chrome 启动 `--remote-debugging-port=9222`（首次使用引导 UI，对标 TCC 引导体验），Playwright `connect_over_cdp` 挂载。

---

## 3. 架构分层

```
L0 浏览器操作层（本设计核心，可独立上线）
   Playwright CDP + DOM 动作集 + aria 快照（浏览器自带结构化文本，零 token 浪费）

L1 站点适配层
   每平台一个适配器（选择器/流程/订单状态标记），版本化可热修

L2 业务层（与具体平台无关）
   任务规划(write_todos) / 确认卡(HITL) / 偏好记忆(memory)
   预算护栏 / 订单追踪 / 失败恢复

L3 前端展示层
   SSE 工具事件 / 订单确认卡 / 订单状态卡 / 购物步骤时间线
```

---

## 4. DOM 动作集（工具接口草案）

```
browser_navigate(url)
browser_snapshot()                # 返回当前页面 aria 快照（结构化文本+元素 ref）
browser_click(ref)                # 按 snapshot 里的元素 ref 点击
browser_fill(ref, text)           # 表单/搜索框输入
browser_select(ref, option)       # 下拉/规格选择
browser_scroll(direction, amount)
browser_extract(ref | selectors)  # 结构化抽取（价格/商品卡/订单字段）
browser_wait(condition, timeout)  # 等待元素/URL/文本出现
browser_read_page()               # 截取当前页面元素截图 → 交多模态模型理解
```

约定：
- 元素定位一律基于 `browser_snapshot()` 返回的 ref（aria 快照模式，对标 Playwright MCP），**不裸用 CSS selector**——快照文本几百 token 即让模型"看清"页面；
- 浏览器会话与聊天会话 1:1，SSE 每步发 `{event:"browser", step, url, title}` 心跳；
- 复用现有工具类别机制，新增 `browser` 类别。

## 5. 核心流程（点外卖半自动示例）

```
用户: "点一份老规矩的瑞幸生椰拿铁"

1. 意图解析 → 任务规划(write_todos): 搜索→确认规格→加购→下单→追踪
2. browser_navigate(美团外卖) → snapshot 确认登录态
   └─ 登录失效 → 交还用户："请在浏览器里登录后告诉我"
3. memory 读取偏好: {店铺, 品名, 规格: 大杯/少冰/标准糖, 地址: 办公室}
4. 搜索 → extract 商品卡 → snapshot 呈现匹配结果
5. 进店 → 选规格 → 加购
   └─ 规格缺货/价格变动 → 汇报 + options 卡片让用户选替代
6. 结算页 → extract {商品/规格/价格/配送费/地址/预计送达}
7. 【订单确认卡 HITL】
   ┌─────────────────────────────┐
   │ 瑞幸咖啡(办公室店)            │
   │ 生椰拿铁 大杯/少冰/标准糖 ×1  │
   │ ¥16.5 含配送 ¥2  预计 25 分钟 │
   │ 地址: XX大厦 12F（默认地址）  │
   │ [确认下单] [修改] [取消]      │
   └─────────────────────────────┘
8. 用户点确认 → 提交订单 → 支付页出现在真实浏览器
   → Agent 提示"请在浏览器完成支付"
9. browser_wait(订单成功标记) → 轮询订单状态 → SSE 通知"已下单/配送中"
```

**关键安全点**：第 6→7 步之间 Agent 无权跳过；第 8 步支付动作 100% 人工。

## 6. 安全设计

### 支付红线
| 动作 | 策略 |
|------|------|
| 搜索/比价/加购/生成订单 | 可自动 |
| 提交订单 | 确认卡强制 HITL，展示全量字段 |
| 支付 | **永久人工**；Agent 仅在支付后从 DOM 验证订单状态 |
| 密码/免密支付设置页 | 进入即停，不读取不操作 |

### 金额护栏
- 设置项：`shopping_per_order_cap`（单笔上限，默认 ¥200）、`shopping_monthly_cap`（月度）
- 结算价 > 上限 → 确认卡升级为二次确认；超月度 → 直接拒绝并汇报

### 地址与账号
- 确认卡必须展示收货地址；**禁止静默修改默认地址**
- 每次下单用 memory 里的快照比对，地址不一致 → 询问
- 永不触碰：账号设置、绑定手机、支付方式管理页

## 7. 偏好记忆与例行复购

- 复用 `memory.py`，结构化 key：`shopping_pref.{platform}.{item}` = {店铺, 规格, 常用地址, 最近价格}
- "老规矩"链路：意图"再来一杯/老规矩" → 读偏好 → 直接跳到第 5 步流程（仍过确认卡）
- 例行复购：`schedule_task` 定时触发（如工作日 9:30 咖啡），流程同上；**无人值守模式下只生成确认卡等待用户上线确认，不自动提交**

---

## 8. 风控与验证码：人工接管

- 滑块/短信验证出现 → Agent 停止操作，通知用户"请在浏览器完成验证"，轮询等待验证通过的 DOM 标记后继续
- 拟人化：DOM 级操作本身无需轨迹拟人；节奏上保留自然间隔（点击间随机 300-800ms）
- 平台 ToS 明确禁止自动化 → 产品内明示风险：操作节奏克制、频次护栏（`shopping_daily_actions_cap`），降低账号风控概率

---

## 9. 失败处理矩阵

| 情况 | 处理 |
|------|------|
| 登录失效 | 暂停 + 交还用户登录，恢复后从断点继续 |
| 商品下架/缺货 | 汇报 + options 卡片提供替代（同店相似/换店） |
| 价格 vs 确认卡漂移 | 涨幅 >5% → 重新确认；≤5% → 继续并在结果中说明 |
| 页面改版（适配层失效） | 站点适配器健康自检失败 → 回退通用 aria 快照循环，同时上报适配器需更新 |
| 支付超时（5 分钟） | 订单自动取消（平台行为），通知用户 |
| 提交后无响应 | 不重试提交（防重复下单）→ 查订单列表页确认是否已生成 |

## 10. 产品模式分层

| 模式 | Agent 职责 | 人工动作 | 适用 |
|------|-----------|----------|------|
| 纯辅助 | 搜索比价，输出对比卡片 | 全程 | 高客单价 |
| 半自动（默认） | 到"订单已生成，待支付" | 确认卡 + 支付 | 一般购物/点外卖 |
| 例行复购 | 定时备单，生成确认卡 | 上线确认 + 支付 | 老规矩咖啡等 |

## 11. MVP 分期

| 阶段 | 范围 | 说明 |
|------|------|------|
| **阶段1** | CDP attach 引导 + 美团/饿了么网页版半自动点外卖（含老规矩复购）+ 确认卡 + 支付后订单验证 | 最简场景：单店、地址固定、金额小、价值直接 |

## 13. 风险预录

1. **页面改版**是最大维护成本 → 站点适配器版本化 + aria 快照通用兜底双保险；
2. **风控误杀**：真实浏览器已最小化风险，仍需频次护栏 + 用户风险明示；
3. **重复下单**是最高危操作错误 → 提交动作全局幂等锁（复用 `_TOOL_LOCKS` 模式），失败只查不重提；
4. **Chrome 调试端口引导**：需检测浏览器是否带 `--remote-debugging-port` 启动，引导 UI 含"一键以调试模式重启浏览器"（用户确认后执行，未保存表单会丢失需提示）；
5. **多浏览器并存**（Chrome/Edge/Arc）→ MVP 仅支持 Chrome，其余提示不支持。
