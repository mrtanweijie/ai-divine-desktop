## 1. 方法

不靠读 CSS 猜问题，而是**实测渲染**：

1. 用项目同款 WeasyPrint 66 把四套模板渲染为 PDF（011/013/014 各 4 页、012 为 3 页，与各自声明的页面映射一致）；
2. 以 110dpi 转 PNG 逐页目视；
3. 用 PyMuPDF 提取**文本 bbox 与矢量绘制对象坐标**做数值核验——凡「看起来不对」的，一律量到 pt 级；
4. 修复后重渲染，用同一套量测脚本复核。

四套模板在 `docs/` 中定位为**设计样张**（`docs/README.md` 的「样张」区），docgen 管线不直接消费（管线走 `app/docgen/pdf/pdf_themes/*.css` + `recipes.py`），因此问题定性为**视觉与规范问题**，不影响运行时。

## 2. 问题清单

### P0 — 渲染缺陷（肉眼可见的破版）

#### 2.1 013 / 014 封面收底带文字被裁切

**现象**：收底带最左侧文字贴到纸张边缘被切掉。

**实测**：带内首段文字 `x0 = 0.00pt`，而正文左边距为 `51.02pt`（18mm）。013 的收底带横跨 `x 0–210mm`（满幅），说明文字没有拿到 18mm 内边距。

**根因**：`.cover-band { display: table; width: 210mm; box-sizing: border-box; padding: 12px 18mm }`。
CSS 规范中 `box-sizing` **对 table 盒子不生效**，`width` 是内容宽度，加上左右各 18mm 的 padding 后 border box 变成 **246mm**；作为 running element 放进 210mm 宽的 `@bottom-center` 后居中，左右各溢出 18mm，文字正好被推到 `x = 0`。

**修复**：`width: 174mm`（= 210 − 18×2），border box 恰好 210mm 满幅。013 / 014 同改。

#### 2.2 012 页脚折行

**现象**：左下角「{{期刊名 / 学报名称}} · {{卷期号}}」断成 2 行（断在「卷期 / 号」中间）；右下角「第 1 页（共 3 页）」断成 **3 行**（「第 1 页」/「（共 3」/「页）」），文字下探到 `y = 824pt`（页高 841.89pt），几乎顶到纸边。

**根因**：`@bottom-left` 与 `@bottom-right` 各自 `padding: 0 20mm`，两个盒子共占 80mm 横向留白，可用宽度不足。

**修复**：改为**单向内侧留白**——`@bottom-left { padding: 0 0 0 20mm }`、`@bottom-right { padding: 0 20mm 0 0 }`。修复后两者均单行，`y = 814.23pt`。

#### 2.3 012 三线表底线错位（学术规范破坏）

**现象**：表 1 的收尾粗线画在**表注下方**，而不是最后一行数据下方——三线表规范要求注释在线外。

**实测**：最后数据行文本 `y = 662.32`，表注 `y = 688.70`；1.5px 近黑收尾线落在 `y = 677.45`（灰分隔线在 `y = 655.29`）。

**根因**：表注写成 `<tr class="note-row">` 留在 `tbody` 内，于是 `.table3 tbody tr:last-child { border-bottom: 1.5px solid }` 命中的是**注释行**而非数据行。表 2 无注释行所以正常——这是个条件触发的隐蔽缺陷。

**修复**：表注移出 `<table>`，改为 `<div class="tbl-note">`（与 011/013/014 的表注写法统一）。修复后收尾线回到 `y = 682.85`（最后数据行下方），表注在 `y = 688.70` 线外。

#### 2.4 013「关键洞察」编号折行

**现象**：洞察 1 的「洞察 1」单行，洞察 2/3/4 却折成「洞察」+「2」，导致编号与标题错位。

**根因**：`.i-no { width: 46px }`（= 34.5pt）。实测「洞察」二字宽 23.19pt，加空格与数字后「洞察 2」约需 33.3pt——**仅剩 1.2pt 余量**。数字字形宽度不同（「1」窄于「2/3/4」），余量耗尽即折行。

**修复**：`width: 64px` + `white-space: nowrap`。四个洞察编号全部单行对齐。

#### 2.5 占位符括号不平衡 / 嵌套

**现象**：渲染后残留多余花括号，视觉上像语法错误。

**实测**：`{{{{成本项}}}` 之类**四重左括号 + 三重右括号**共 10 处，分布：
- 011：4 处（摘要、正文段落、结论项）
- 012：2 处（引言段、方法段；其中方法段少一个闭合括号，整行不平衡）
- 013：5 处（洞察 2/4 标题与正文、行动建议表 2 行）
- 014：2 处（关键发现 03 标题与正文）

**根因**：模板混用了两种写法——「扁平」`{{甲}} 与 {{乙}}` 与「外层包裹整段 + 内层命名槽」`{{整段 {{槽位}} 整段}}`。后者在书写时极易多写或少写一个括号，四重括号正是这么来的。

**修复**：**统一为扁平不嵌套**，并把该约定写进四个文件的头部注释。共展开 10 处四重括号、剥掉 8 处外层包裹、补齐 1 处缺失闭合。终检：四文件不平衡行 0、四重括号 0、孤立括号 0。

> 附带说明：`docs/templates/` 是设计样张，无运行时消费者，因此约定调整不涉及代码改动。

## 4. 过程记录（需注意）

修复占位符时，最初用了一个批处理脚本「若最外层 `{{…}}` 内仍含占位符则剥壳」。该规则在**同一行存在多个并列占位符**时会误配首尾括号，造成大面积内容损坏（例如 `{{作者姓名}}　（学号：{{2023XXXXXX}}）` 被拆坏）。四个文件当时均未入库（`git status` 为 `??`），无法回滚，最终**依据会话中读取的原始内容整体重建**，并一次性带上全部修复。

教训：这类文本改写不能用「首尾配对」的启发式，必须按占位符逐个匹配（`\{\{[^{}]*\}\}`）或先做括号配对校验。已在本文档留档，后续修改模板请先 `cp` 备份。

另：修复期间这四个文件被外部页面编辑器持续注入 `data-page-node-id` 属性；重建后的版本不含该属性。若该编辑器仍在运行，重新保存时会再次注入。

## 6. 修订记录 · 013 首页 KPI 带回归（2026-09-13 追加）

**报告来源**：用户反馈「经营数据分析报告的 PDF 第一页样式有问题」。

**定位结果**：§2.1 修复 013 封面时，我把 `.kpi-strip` 从「流内 table」改成了「absolute + `left/right` + `display: table`」，这引入了一处新缺陷——**WeasyPrint 不会用 `left`/`right` 反推 table 的宽度**，table 退化为按内容收缩，且 `table-layout: fixed` 因宽度不确定而失效。

**实测对比**（首页 KPI 带横向量测）：

| | 顶线宽度 | 三条竖分隔线位置 | 四栏宽度 |
| --- | --- | --- | --- |
| 本次改动前（原始版本） | 481.89pt | 177.17 / 297.64 / 418.11 | 等宽 120.47pt ✓ |
| 我的版本（有缺陷） | **353.03pt**（仅内容宽的 72%） | 132.82 / 235.89 / 320.35 | **81.79 / 103.08 / 84.46 / 83.71pt 不等** ✗ |
| 修订后 | **493.23pt**（满宽） | 174.33 / 297.64 / 420.94 | **等宽 123.31pt** ✓ |

顺带暴露的不一致：同文档第 2 页的 `.ov-strip` 一直是满宽 493.23pt / 等分 123.31pt，于是**同一套模板里两个「关键指标带」一个 353pt 一个 493pt**，右端差了 140pt。修订后两者完全对齐。

**修复方式**：拆分职责——外层普通块负责定位与定宽，内层 table 用 `width: 100%` 吃满。

```html
<div class="kpi-anchor">
  <div class="kpi-strip"> …4 × .kc… </div>
</div>
```
```css
.kpi-anchor { position: absolute; left: 18mm; right: 18mm; bottom: 18mm; }
.kpi-strip { display: table; width: 100%; table-layout: fixed; border-top: 2px solid var(--rule-dark); }
```

**同时调整垂直节奏**：上一轮把内容块下移（`padding-top: 56mm`）又把 KPI 带锚底，结果中部留下 **313.2pt = 110.5mm** 的空白（占页高 37%），页面被切成互不相连的三块。改为在「页眉下沿 ≈9mm → KPI 带上沿 ≈239mm」之间垂直居中（`padding-top: 83mm`），上下留白约 89mm / 81.5mm，接近对称，读作刻意的极简而非「没排满」。

**验证**：页数仍为 4；第 2–4 页文本与修订前逐页比对**完全一致**（无回归）；首页 KPI 带与第 2 页指标带宽度、分栏完全对齐。

### 新增的 WeasyPrint 坑（已补入项目长期记忆）

> **不要在 absolute 元素上直接写 `display: table` + `left`/`right`。** WeasyPrint 不会用两个偏移量推导 table 宽度，会退化成 shrink-to-fit，同时令 `table-layout: fixed` 失效。需要「锚定 + 满宽等分」时，用外层普通块承接 `position/left/right`，内层 table 写 `width: 100%`。

### 反思

上一轮修复时，我对 013 首页只做了「目视 + 关键点量测」，**没有把改动前后的元素几何做逐项回归比对**——KPI 带的宽度变化因此在交付前未被发现。后续改封面类布局，应把「改动前后的矢量元素 x/y 范围做 diff」作为固定验收步骤。
