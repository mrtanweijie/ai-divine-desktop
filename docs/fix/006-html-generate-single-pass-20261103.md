# html_generate 一次成稿：排版自动收敛，软建议不再逼模型重写

> 编号：046 ｜ 类型：fix ｜ 日期：2026-11-03 ｜ 状态：已实施
> 现象：生成报告后立刻被告知「27 种硬编码色值 / 12 种字号 / 手调间距」，于是又调用一次 `html_generate` 覆盖保存
> 关联：`divine-server/app/tools/scripts/html_generate.py`、`ux_html.py`、`tests/test_ux_html.py`

---

## 1. 问题：一次生成被迫变两次调用

原流程（`scripts/html_generate.py` 与 `scripts/ux_html.py` 同构）：

```python
final_content, scaffolded = inject_scaffold(content, style)
warnings = lint_html(content, scaffolded=scaffolded)
output_path.write_text(final_content)            # 先落盘
if warnings:
    message += "静态校验发现以下问题，请修正后重新调用 html_generate 覆盖保存：…"
```

即：**写文件 → 报问题 → 让模型重写整段 HTML → 再写一次**。用户侧看到的就是
「执行完成 · 250ms」紧接着「执行完成 · 225ms」——两轮工具调用、两倍 token 与等待，
而第二次只是把字号/间距调一调。

讽刺的是 `lint_html` 自己的注释写着「误报会让模型反复重写浪费轮次」——原流程恰恰在制造它。

## 2. 修法：分三类，各归各位

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| **纯数值**（可确定性收敛） | 字号 12 档、间距 5/6/9/10/11/14px | **落盘前自动收敛**，一次成稿 |
| **建议**（改了会动设计意图） | 27 种硬编码色值、Google Fonts、国外 CDN | 只作为**可选建议**回传，明确「文件已保存，无需重新生成」 |
| **硬伤**（预览会崩/成品不合格） | `localStorage`、未替换的 `{{}}`/占位文本 | 仍然要求修正后重调（这轮重写是应该的） |

### 2.1 自动收敛（`ux_html.normalize_visual_scale`）

- **字号**：超过档数上限时，按系统提示【2】的阶梯吸附：`12/14/15/18/24/32`（移动端 `11/13/15/17/20/28`），
  等距取小档。**不自己聚类**——收敛结果必须与设计规范同一套数值，否则「规范化」反而制造新规范。
- **间距**：非 4 倍数的手调值就近落档（≤64 取 4/8/12/16/24/32/48/64，>64 按 4 的倍数取整）；
  0/1/2/3 与 4 的倍数原样保留（边框细线、微调偏移）。
- **不碰色值**：改色会动品牌色/语义色，交给建议提示。
- 只改 `font-size` 与 `padding/margin/gap` 的 px，其余字节不动（含原有空格风格）。

### 2.2 文案分级

```text
HTML 页面已生成（已注入 Linear 风格 token 基座…）（已自动收敛排版：字号 12 档 → 按 12/14/15/18/24/32 阶梯收敛、间距手调值（5px/6px/9px/10px/11px/14px）已对齐档位）
```

- 硬伤 → `以下问题会导致预览异常或成品不合格，请修正后重新调用 … 覆盖保存`
- 建议 → `另有可选优化建议（文件已保存，无需重新生成）`
- 载荷同时给出 `data.scale_notes` / `data.blocking_issues`，`warnings` 只剩「建议」，前端或模型都不会再误读成必须重写。

### 2.3 防漂移

`TYPE_LADDER` 与系统提示【2】必须同一套数字：`tests/test_ux_html.py::test_type_ladder_matches_system_prompt`
会从 `_UX_HTML_RULES` 与 `_HTML_PAGE_RULES` 里取出 `H1 …` 那一行逐档比对，改任一侧都会红。

## 3. 验证

**端到端**（复刻用户那份报告的违规规模：12 种字号 + 6 种手调间距 + 27 种硬编码色值）：

| | 修前 | 修后 |
| --- | --- | --- |
| 工具调用次数 | 2（生成 → 报错 → 重生成） | **1** |
| 落盘字号 | 12 种（11.5…30） | **6 档 12/14/15/18/24/32** |
| 落盘间距 | 5/6/9/10/11/14 | **4/8/12/16** |
| 返回文案 | 「请修正后重新调用…覆盖保存」 | 「已自动收敛排版：…」+ 可选建议 |
| `blocking_issues` | — | `[]` |

**单测**（`tests/test_ux_html.py` 新增 7 例）：字号收敛到阶梯、间距落 4 格、合规页面零改动、
色值不被改、大间距（100px）保留、收敛后字号/间距两类 lint 提示消失、`hard_failures` 只认硬伤、
阶梯与提示词一致。

## 4. 边界

1. **收敛不是排版重做**：只把超档的数值吸附到最近档位，不重排布局、不改字重行高。
2. **色值仍可能超标**：27 色不会被自动合并——把品牌色/语义色糊成 `--c1…--c27` 属于 token 化装样子，
   比超标更糟。这一项保持「建议」。
3. `ux_html`（交互原型）走同一套逻辑，移动端用其专属阶梯与「只抓奇数」的间距规则。
