# 文档生成域重构方案

> 目标：把平铺在 `divine-server/app/` 根目录的 12 个文档生成模块收敛为 `app/docgen/` 子包。
> 状态：**已于 2026-09-01 实施完成**（4 个批次提交 + 打包冒烟）。评审修正与实际执行差异见文末「九、实施记录」。

## 一、背景与债务规模

`divine-server/app/` 根目录目前堆积了 12 个文档生成模块，共 **14,043 行，占后端总量（48,383 行）的 29%**。它们与 Agent 主线无关，却平铺在与 `main.py`、`config.py`、`schemas.py` 同级的包根目录。

| 模块 | 行数 | 文件数 | 备注 |
| --- | --- | --- | --- |
| `resume_themes/` | 3,761 | 20 | 最大子包 |
| `pdf_tool/` | 2,960 | 10 | |
| `pdf_theme_manager.py` | 2,039 | 1 | 全后端最大单文件 |
| `ppt_renderer/` | 1,949 | 6 | |
| `pdf_renderer/` | 1,451 | 7 | |
| `chart_svg.py` | 532 | 1 | |
| `word_themes.py` | 508 | 1 | |
| `word_elements.py` | 318 | 1 | |
| `word_markdown.py` | 297 | 1 | |
| `pdf_export.py` | 156 | 1 | 被 `api/sessions.py` 引用 |
| `pdf_preview.py` | 58 | 1 | 被 `api/files.py` 引用 |
| `ppt_themes.py` | 14 | 1 | |

另含静态资源目录 `pdf_themes/`（12 个 CSS / HTML 模板文件，无 Python 代码）。

对比：Agent 主线 `agent/` 共 9,202 行。文档生成域是其 1.5 倍。

## 二、耦合分析（重构可行性依据）

2026-09-01 沿引用链逐模块验证，结论：**这笔债是纯组织问题，不是架构问题**。

### 2.1 核心层零引用

`agent/`、`db/`、`llm/`、`mcp/` 对上述 12 个模块**没有任何 import**。Agent 与文档生成完全解耦，通过 `tools/registry` 间接调用。

### 2.2 调用方仅 7 处

| 调用方 | 引用目标 |
| --- | --- |
| `tools/scripts/pdf_render.py` | pdf_tool、pdf_renderer、pdf_theme_manager |
| `tools/scripts/pdf_generate.py` | pdf_tool |
| `tools/scripts/presentation.py` | ppt_renderer |
| `tools/scripts/word_document.py` | word_themes、word_elements、word_markdown |
| `tools/scripts/generate_chart.py` | chart_svg |
| `api/sessions.py:17` | pdf_export（`render_markdown_pdf`） |
| `api/files.py:10` | pdf_preview |

### 2.3 反向依赖仅 2 处

全部集中在 `pdf_tool/engine.py`：

```python
from ..config import settings_store      # 第 10 行
from ..llm import DeepSeekLLM, MockLLM   # 第 11 行
```

文档生成域内部互引（如 `pdf_tool/* → pdf_theme_manager`、`pdf_tool/engine.py → resume_themes`、`ppt_themes.py → ppt_renderer`）随包整体移动，层级不变。

## 四、实施步骤

按依赖从少到多分四批，每批独立提交、独立验证。

### 第 1 批：word + chart（依赖最少）

1. `git mv` word 三件套 → `app/docgen/word/`，chart_svg.py → `app/docgen/chart/svg.py`
2. 修调用方：`tools/scripts/word_document.py`、`tools/scripts/generate_chart.py`
3. 全量测试 → 提交

### 第 2 批：ppt

1. `git mv` ppt_renderer/ → `app/docgen/ppt/renderer/`，ppt_themes.py → `app/docgen/ppt/themes.py`
2. 修内部互引（ppt_themes → renderer 层级不变）与调用方 `tools/scripts/presentation.py`
3. 全量测试 → 提交

### 第 3 批：pdf（最复杂）

1. `git mv` pdf_tool/、pdf_renderer/、pdf_theme_manager.py、pdf_export.py、pdf_preview.py、pdf_themes/ → `app/docgen/pdf/`
2. **关键改动**：`engine.py` 顶部两行 `..config` → `...config`、`..llm` → `...llm`（唯一需要动脑的导入）
3. 修内部互引（pdf_tool ↔ theme_manager、engine → resume_themes 暂留旧路径，第 4 批处理）
4. 修调用方：`tools/scripts/pdf_render.py`、`tools/scripts/pdf_generate.py`、`api/sessions.py`、`api/files.py`
5. **同步 `divine-server.spec`**（见第五节）
6. 全量测试 + 打包验证 → 提交

### 第 4 批：resume

1. `git mv` resume_themes/ → `app/docgen/resume/`
2. 修 `docgen/pdf/engine.py` 中的 `from ..resume_themes` → `from ..resume`
3. **同步 spec** → 全量测试 + 打包验证 → 提交

### 第 5 批（可选，过渡期后）：删除 shim

见 6.2 兼容层策略。

## 五、硬约束与风险

### 5.1 ⚠️ PyInstaller spec 必须同步（最大的坑）

`divine-server.spec` 的 `hiddenimports` 显式列出了约 20 个文档生成模块路径：

```
app.chart_svg / app.pdf_theme_manager / app.pdf_tool.* / app.ppt_renderer.*
app.resume_themes.* / app.word_themes / app.ppt_themes ...
```

`datas` 中含 `(app/pdf_themes, "app/pdf_themes")`。

**不改 spec：本地开发一切正常，打包产物运行时 `ModuleNotFoundError`**——测试环境无法发现，只能靠打包冒烟验证。每批移动都必须同步更新 spec 对应条目，并在该批次的验证步骤中包含 `bash build-sidecar.sh` + 桌面端冒烟启动。

### 5.2 工具脚本的 in-process 导入路径

`tools/base.py` 的 `_run_in_process` 按模块名 `importlib.import_module(script_module)` 动态导入轻量工具脚本。工具脚本本体在 `tools/scripts/` 不动，但其内部 `from app.pdf_tool import ...` 一类的绝对导入（frozen 环境兜底路径）需全局搜索确认：`grep -rn "from app\.\(pdf\|ppt\|word\|resume\|chart\)" tools/`。

### 5.3 pdf_theme_manager.py 单文件 2,039 行

本次重构**只移动、不拆分**，控制风险。该文件主题混杂（主题解析 + 渲染参数 + 版式规则），建议作为后续独立任务拆为 `theme_parser.py` / `render_params.py` / `layout_rules.py`，拆分时已有 `docgen/pdf/` 边界兜底。

### 5.4 测试引用

28 个测试文件引用文档生成模块（`test_pdf_design`、`test_pdf_content_sections`、`test_travel_theme`、`test_presentation_render`、`test_design_rules`、`test_covers`、`test_resume_models` 等）。靠 6.2 的 shim 免改；删除 shim 的批次再统一替换测试导入。

## 六、兼容层策略

### 6.1 渐进迁移原则

每批移动后，旧路径保留 re-export shim（如 `app/pdf_tool/__init__.py` 内容为 `from ..docgen.pdf import *`），保证未及时更新的引用方不炸。

### 6.2 shim 生命周期

- shim 仅限过渡，**保留一个发布版本**（对照 `release-notes.md` 版本节奏）
- 删除 shim 的批次必须：全量替换 tests/ + tools/ 中的旧导入 → 全量测试 → `bash build-sidecar.sh` 打包冒烟
- `app/docgen/__init__.py` 不做 re-export，新代码一律从明确子路径导入
